# Кабинет учителя

Учебная платформа с тренажёрами по химии и биологии, личными результатами и отдельными инструментами учителя. Универсальные тесты открываются через `test.html?id=<testId>`, а их содержание хранится в `data/tests/*.json`. Интерфейс публикуется на GitHub Pages; необязательные аккаунты и облачная синхронизация работают через Supabase.

## Структура

- `index.html` — главная и резервный каталог без JavaScript;
- `test.html`, `results.html` — универсальный тест и история результатов;
- `account.html`, `dashboard.html` — вход и личный кабинет ученика/учителя;
- `assets/js/` — движок, типы вопросов, оценивание, хранение и каталог;
- `assets/css/` — общие стили;
- `data/catalog.json` — разделы и карточки главной;
- `data/tests/` — учебные данные универсальных тестов;
- `scripts/` — проверки данных, ссылок, модулей и локальный сервер;
- `tests/unit/` — модульные тесты на встроенном `node:test`;
- `tests/smoke/` — ключевые браузерные сценарии Playwright;
- `config/asset-version.json` — единая версия браузерных JS-модулей;
- `supabase/migrations/` — схема таблиц, RLS и права доступа;
- `supabase/functions/` — защищённое создание аккаунта учителя и учеников;
- `.github/workflows/quality.yml` — обязательные проверки PR и `main`.

Старые автономные реализации удалены после проверки универсальных версий. Их прежние URL сохранены как небольшие совместимые страницы-переходы, поэтому старые закладки продолжают вести на актуальный `test.html?id=…`.

Общий реестр поддерживает типы `single`, `multiple`, `matching`, `number`, `text` и `sequence`. Необязательный блок `content` с форматами `text` и `formula` выводится безопасно через `textContent` для любого типа вопроса. `formula` — формат отображения, а не отдельный тип ответа.

## Локальный запуск

Требуется Node.js 22 или новее.

```bash
npm ci
npm run serve
```

После запуска сайт доступен по адресу `http://127.0.0.1:4173`.

`npm ci` также устанавливает зафиксированную версию `@supabase/supabase-js`. Браузерный bundle уже включён в репозиторий; после обновления зависимости его нужно пересобрать командой `npm run build:vendor`.

## Аккаунты и облачное сохранение

Вход является необязательным. Без аккаунта все тренажёры, прогресс и локальная история продолжают работать через `localStorage`. После входа:

- незавершённая попытка синхронизируется между устройствами;
- завершённые результаты сохраняются в облачной истории;
- ученик видит назначенные работы, сроки, свою статистику, последние попытки и связанные классы;
- учитель создаёт классы и аккаунты учеников, выдаёт выбранный вариант теста в режиме тренировки или теста с датой сдачи, видит результаты и простую динамику.

Ученику не требуется личный e-mail: логин преобразуется во внутренний технический адрес домена `.invalid`, который никогда не используется для почтовой доставки. Первый аккаунт учителя создаётся по одноразовому коду владельца; далее ученические аккаунты создаёт только авторизованный учитель.

В открытом репозитории допустим только publishable key Supabase. Он не является секретом и работает исключительно вместе с RLS. Secret/service-role keys, пароли, одноразовый код, имена учеников и названия реальных классов в репозиторий не добавляются.

Облачная схема использует таблицы `profiles`, `classrooms`, `classroom_members`, `assignments`, `attempt_progress` и `attempts`. На всех публичных таблицах включён RLS:

- ученик читает только собственный профиль, прогресс и результаты;
- учитель читает результаты только учеников своих классов;
- ученик читает назначения только тех классов, в которые он добавлен;
- создать назначение может только учитель-владелец класса;
- параметры завершённой назначенной попытки повторно проверяются в базе;
- завершённые попытки неизменяемы из браузера;
- административное создание пользователей выполняется только Edge Functions.

Клиентские результаты нельзя считать криптографически защищёнными от намеренной подмены: сами тесты и проверка работают в публичном браузере. RLS обеспечивает изоляцию данных разных пользователей, но не заменяет прокторинг.

Личная попытка и каждое назначение одного теста имеют отдельный `scope_key`: `personal` или `assignment-<id>`. Поэтому начало назначенной работы не заменяет самостоятельную незавершённую попытку. После срока работа остаётся доступной, а сдача отмечается как выполненная с опозданием.

## Команды проверки

```bash
npm run assets:check      # единая версия и существование локальных JS-модулей
npm run build:vendor      # пересборка закреплённого browser bundle Supabase
npm run validate:data     # каталог и все data/tests/*.json
npm run validate:links    # каталог, резервные карточки, href и src
npm run validate:modules  # точки входа, импорты, циклы и специализация по test.id
npm run test:unit         # оценивание, нормализация, выборка и каталог
npm run test:smoke        # ключевые страницы в Chromium
npm run check             # все проверки, не требующие графического браузера
```

Smoke-тесты сами запускают временный статический сервер. Для первого локального запуска Playwright может потребоваться команда:

```bash
npx playwright install chromium
```

## Добавление универсального теста

1. Создать `data/tests/<testId>.json` по существующей схеме.
2. Использовать постоянные уникальные ID вопросов, разделов и вариантов.
3. Добавить карточку в `data/catalog.json` с URL `test.html?id=<testId>`.
4. Добавить ту же видимую ссылку в резервный каталог `index.html`.
5. Выполнить `npm run check` и `npm run test:smoke`.

Числовой ответ хранится в прогрессе как строка. Тип `number` принимает обычную десятичную запись с точкой или запятой, но отклоняет экспоненциальную, шестнадцатеричную и смешанную запись. Ограничения `integer`, `min`, `max` и `tolerance` задаются в JSON вопроса и применяются единым обработчиком типа.

Текстовый ответ также хранится как исходная строка ученика. Для сравнения обработчик `text` отдельно применяет только явно заданные настройки: учёт регистра, обрезку краевых пробелов, свёртку внутренних пробелов и приведение типографских знаков минуса к `-`. Нечёткое сравнение, исправление опечаток, перестановка слов и преобразование `6+` в `+6` не выполняются.

### Вопрос на последовательность

Тип `sequence` хранит постоянные ID элементов и оценивает каждую правильную позицию одним баллом. Отображаемый текст можно изменить в новой версии данных, не разрушая совместимое сохранение. Ответ в прогрессе имеет универсальный вид:

```json
{
  "order": ["methane", "ethane", "propane", "butane"],
  "touched": true
}
```

Пример вопроса:

```json
{
  "id": "alkane-sequence-001",
  "section": "sequence",
  "type": "sequence",
  "text": "Расположите ациклические алканы в порядке увеличения числа атомов углерода.",
  "items": [
    { "id": "methane", "text": "CH₄", "format": "formula" },
    { "id": "propane", "text": "C₃H₈", "format": "formula" },
    { "id": "ethane", "text": "C₂H₆", "format": "formula" },
    { "id": "butane", "text": "C₄H₁₀", "format": "formula" }
  ],
  "correct": ["methane", "ethane", "propane", "butane"],
  "sequence": { "shuffleInitial": true, "scoring": "position" },
  "explanation": "Каждый следующий член ряда содержит на одну группу CH₂ больше."
}
```

`items[].id` должны быть непустыми и уникальными, а `correct` — полной перестановкой этих ID. При восстановлении обработчик сохраняет известные уникальные ID в прежнем относительном порядке, удаляет неизвестные и детерминированно добавляет потерянные элементы. Начальная перестановка создаётся один раз для попытки и не меняется при повторном рендере.

Основной доступный способ управления — кнопки «выше» и «ниже» с активной областью не менее 44 × 44 px. Они работают с Tab, Enter и Space; после перемещения focus остаётся на соответствующем элементе. Перетаскивание мышью является дополнительным способом и не требуется на сенсорном устройстве.

При позиционном оценивании четырёх элементов максимум равен четырём баллам. Любой не полностью правильный вопрос целиком включается в список ошибок, даже если часть позиций получила баллы.

Тест по гибридизации находится в `data/tests/hybridization-theory.json`: семь тематических разделов по 15 вопросов и восемь вариантов. Старый адрес `hybridization-theory.html` переводит на универсальную версию.

Тренажёр по ОВР находится в `data/tests/redox-trainer.json`: четыре раздела по 15 вопросов и пять вариантов. Старый адрес `trainer.html` переводит на универсальную версию.

Тренажёр по гомологии алканов находится в `data/tests/alkane-homology.json`: 12 тематических разделов по 15 заранее записанных вопросов и 13 вариантов. Старый адрес `alkane-homology.html` переводит на универсальную версию.

Биологический тест на сопоставление находится в `data/tests/biology-matching.json`: три тематических matching-задания содержат все 27 соответствий исходного материала, а четыре варианта позволяют пройти весь тест или отдельный раздел. Прогресс и история используют тот же формат, что и химические тренажёры; при входе он дополнительно синхронизируется с аккаунтом.

На универсальную платформу также перенесены `organic-review`, `inorg-nomenclature` и `organic-classification`. Прежние адреса сохранены как страницы-переходы без дублирования движка и банка заданий.

`validate:data` использует те же `validateTestDefinition`, `validateCatalog` и реестр типов вопросов, что и браузер. Научная корректность формулировок по-прежнему требует отдельной предметной проверки.

## Изменение каталога

В `data/catalog.json` поддерживаются статусы `active`, `beta` и `hidden`. Для `active` и `beta` резервная карточка должна присутствовать в `index.html`; для `hidden` она запрещена. Все локальные URL и соответствующие JSON-файлы проверяются автоматически.

## Версия JS-модулей

Текущая версия хранится только в `config/asset-version.json`. Все локальные `script type="module"` и статические импорты должны содержать одинаковый параметр `?v=<version>`.

```bash
npm run assets:check
npm run assets:sync
npm run assets:bump -- 10
```

- `assets:check` ничего не изменяет и завершается ошибкой при пропущенной, разной или неверной версии;
- `assets:sync` приводит подключения к версии из конфигурации;
- `assets:bump` принимает положительное целое число, обновляет конфигурацию и все подключения, затем повторно проверяет граф;
- версия повышается осознанно при изменении клиентских модулей, а не при каждом коммите.

Скрипт не изменяет CSS, JSON, обычные HTML-ссылки и внешние HTTPS-адреса. Повторный запуск детерминирован и не создаёт дополнительный diff.

## Правила публикации материалов

- Не включать в GitHub имена учеников, реальные классы, результаты конкретных людей и другие персональные данные.
- Поля имени и класса допустимы только в защищённом личном кабинете и сохраняются исключительно в Supabase.
- Не хранить в репозитории токены, секретные ключи и административные данные.
- Publishable key не является секретом, но его использование допустимо только при включённом и проверенном RLS.
- Без входа данные остаются только в браузере; после входа синхронизируются с аккаунтом.

## Публикация изменений

1. Изменить файлы в отдельной ветке.
2. При изменении браузерного JavaScript повысить версию через `npm run assets:bump -- <version>`.
3. Выполнить `npm run check`.
4. Выполнить `npm run test:smoke`.
5. Создать pull request в `main`.
6. Дождаться зелёного workflow `Quality gates`.
7. Объединить PR.
8. Проверить опубликованную страницу GitHub Pages.

Workflow контроля качества не публикует сайт и не объединяет PR автоматически. Способ публикации GitHub Pages остаётся прежним.
